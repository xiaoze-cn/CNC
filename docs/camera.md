# RVC SDK 相机采集参数研究与调节建议

本文以项目当前使用的 `PyRVC.X1_CaptureOptions` 为准。参数名称保持 SDK 原名；每次采集实际生效的选项会写入 `metadata/capture.json`。文中不规定一套固定数值，现场调节应以原始图像、条纹调制度、置信度、点云边缘和标准件结果共同判断。

## 采集模式与重复观测

### `capture_mode`

- 选择 SDK 的三维采集模式，决定条纹解码和互反射处理路径。
- 普通模式适合光路干净、以漫反射为主、没有明显深孔或窄槽的表面。
- 抗互反射模式适合高反表面、多路径反射、深孔、窄槽和台阶附近的成片错误深度。
- 抗互反射模式可能降低有效点比例或增加采集时间，不能替代遮光、偏振、HDR 和多视角控制。
- 调整后必须重新检查有效点覆盖、边缘位置和采集耗时；不要只根据画面是否变干净判断模式优劣。

### `scan_times`

- 控制一次采集中的重复扫描或重复观测次数，SDK 文档说明它主要用于需要重复扫描的模式。
- 增加重复观测有助于降低随机噪声和提高平面稳定性，但会增加采集时间、运动敏感性和数据量。
- 转台未完全停止、工件有振动或温漂时，增加次数不能修复姿态变化造成的重影。
- 调节时应同时观察重复扫描之间的点位差、边缘偏移和转台停止时间。

### `smoothness`

- 选择 SDK 的点图整体平滑等级。
- 更强平滑可降低随机表面噪声、让大平面更连续，但会削弱尖锐边缘、孔口和小缺陷。
- 精密计量或缺陷检测应从较弱平滑开始，只有噪声已经影响判差时才增加。
- 调整后要用台阶、孔口和人工缺陷标准件检查几何边缘是否被推平。

## 二维和三维成像

### `exposure_time_2d`

- 设置二维图像曝光时间，官方 SDK 文档标明单位为毫秒。
- 标记、纹理或轮廓过暗时增加；出现饱和、光晕、轮廓膨胀或背景泛白时降低。
- 它只改善二维证据和定位图像，不能直接补偿三维条纹曝光不足。
- 使用 `enable_2d_in_capture` 关闭二维采集时，该参数不会产生可见的二维输出效果。

### `gain_2d`

- 设置二维成像增益，放大二维信号。
- 曝光受运动或同步限制而无法继续增加时，可用增益补偿暗部。
- 增益也会放大传感器噪声、固定图案和反光；通常先调整曝光，再做小幅增益调整。
- 标记分割不稳定时，应同时检查投影照明和背景反射，不能只提高增益。

### `gamma_2d`

- 调整二维灰度响应的非线性，改变暗部和亮部的相对对比度。
- 适合修正相机响应或标记分割中的系统性亮度偏差。
- 不适合解决三维条纹饱和、相位错误或深度噪声。
- 任何 gamma 改动都应在多个材质和亮度条件下重新验证阈值、边界和定位稳定性。

### `exposure_time_3d`

- 设置非 HDR 三维条纹曝光时间，官方 SDK 文档标明单位为毫秒。
- 低反射、深色或远距离区域调制度不足时增加；高反区域饱和、飞点增多或条纹溢出时降低。
- 曝光变长会增加运动模糊和采集时间，不能脱离转台速度单独调整。
- HDR 开启时，它通常作为基础三维曝光或非 HDR 回退参数，具体生效关系以当前采集模式为准。

### `gain_3d`

- 设置三维条纹信号增益。
- 低反射材料无法形成稳定条纹时可以增加。
- 高反金属优先通过曝光、投影亮度和 HDR 扩大动态范围；过高增益会同时放大噪声、饱和和错误对应。
- 调整后应比较置信度分布、无效点比例和同一平面的重复性。

### `gamma_3d`

- 调整三维条纹的灰度响应，用于补偿相机和投影仪的非线性。
- 条纹亮暗不对称、平面残差呈系统性起伏或相位响应偏斜时可以评估。
- 它不是通用去噪参数，也不能替代曝光或投影亮度调整。
- 应使用平面标准件和相位残差验证，不能只凭肉眼观察条纹亮度。

### `projector_brightness`

- 设置非 HDR 三维采集的投影亮度。
- 整体调制度不足、暗色区域无法解码时增加；高光饱和、反射外溢或条纹对比过强时降低。
- 投影亮度和曝光、增益互相耦合，调整一个参数后必须复查另外两个参数的饱和和噪声。
- 二维图像使用投影器时，它也会影响二维标记和纹理的照明，应结合 `use_projector_capturing_2d_image` 判断。

### `use_projector_capturing_2d_image`

- 控制二维图像是否使用投影器辅助照明。
- 标记或纹理需要稳定主动照明时开启有帮助。
- 投影反光干扰标记分割、需要观察真实表面纹理或环境光已经足够时，可关闭。
- 开关变化会改变二维图像的亮度和反射特征，相关定位阈值和质量基线需要一起复核。

### `enable_2d_in_capture`

- 控制三维采集时是否同时获取二维图像。
- 标记定位、曝光诊断、反射分析和二维证据链需要开启。
- 只做快速三维预览、希望减少数据量或采集时间时可以关闭。
- 关闭后不会得到可用于定位和事后曝光分析的二维帧，不能在后处理阶段补回。

## HDR 多曝光

### `hdr_exposure_times`

- 指定 HDR 使用的曝光档位数量；SDK 通过该字段决定是否进入多曝光采集。
- 增加档位可以覆盖更大的反射率范围，但会增加采集时间、运动敏感性和档位切换边界。
- 档位数量应由高反饱和区和低反欠曝区的覆盖需求决定，不应单纯追求档位更多。
- 关闭 HDR 时，应同时确认 `exposure_time_3d` 和 `projector_brightness` 的非 HDR 路径仍满足需求。

### `SetHDRExposureTimeContent(index, value)`

- 设置指定 HDR 档位的曝光时间。
- 高反区域饱和时降低对应档位；低反区域条纹调制度不足时提高对应档位。
- 相邻档位跨度过大可能造成像素选择边界不连续，应检查 HDR 合成后的深度和置信度连续性。
- `index` 必须对应当前 HDR 档位；非法索引或超出 SDK 接受范围时接口会拒绝设置。

### `SetHDRGainContent(index, value)`

- 设置指定 HDR 档位的三维增益。
- 低反档位信号不足时增加；噪声、固定图案或饱和增加时降低。
- 高反金属通常应优先保护短曝光档位，避免所有档位同时放大噪声。
- 调整后要检查每个档位的条纹调制度、饱和比例和最终像素选择结果。

### `SetHDRProjectorBrightnessContent(index, value)`

- 设置指定 HDR 档位的投影亮度。
- 暗部条纹不足时增加；高光饱和、反光明显或投影纹理外溢时降低。
- 应与同一档位的曝光和增益成组调整，否则很难判断是哪一个参数造成变化。
- HDR 档位需要覆盖不同反射率区域，而不是让每个档位使用相同照明强度。

### `SetHDRScanTimesContent(index, value)`

- 设置指定 HDR 档位的重复扫描次数，SDK 文档说明它主要在需要重复观测的模式中使用。
- 工件稳定且随机噪声明显时可以增加；转台振动、工件移动或温漂明显时不宜增加。
- 不同档位使用不同重复策略时，要检查各档位之间的运动误差是否会破坏 HDR 像素选择。

### `GetHDRExposureTimeContent(index)`、`GetHDRGainContent(index)`、`GetHDRProjectorBrightnessContent(index)`、`GetHDRScanTimesContent(index)`

- 这些接口读取指定 HDR 档位的实际内容，用于确认设置是否被 SDK 接受。
- 采集后应优先记录读取到的值，而不是只记录调用时传入的值。
- 读取接口返回无效索引结果时，调用方应停止使用该档位，不要把它当作有效曝光或增益。

## 质量、反射和相位筛选

### `confidence_threshold`

- 设置 SDK 输出点的最低置信度门槛；低于门槛的点会被 SDK 删除。
- 提高门槛通常会减少低置信度飞点和稀疏噪声，但也会丢失暗部、斜面、反射区和遮挡边缘的有效点。
- 降低门槛通常会提高覆盖率，但会把更多不确定点交给后续处理。
- 应结合多视角支持、条纹调制度、边缘偏移和 STEP 偏差决定，不能只看点数。

### `reflection_filter_threshold`

- 控制 SDK 对镜面反射疑似点的过滤强度。
- 反光飞点明显、且正式输出更重视可靠性时可以增加。
- 真实高光几何、孔边和尖锐结构被误删时应降低，并用多视角一致性和空间证据做二次筛选。
- 该参数不能替代遮光、偏振、投影角度和环境光控制。

### `light_contrast_threshold`

- 设置条纹或光照对比度的最低要求；低于要求的区域会被视为无效点。
- 提高门槛可减少弱调制度区域的不稳定深度。
- 降低门槛可保留低反射或斜入射区域的候选点，但不确定点会增加。
- 调节时应同时查看调制度分布和有效覆盖，而不是只观察最终点云密度。

### `filter_range`

- 控制 SDK 的第一类点云噪声过滤尺度；官方说明过滤强度随该参数增大而增强。
- 孤立噪声尺度明显且远离真实边界时可以增加。
- 台阶、孔边、薄壁和尖锐结构附近过强会跨越真实几何边界并误删点。
- 当该算法效果不理想时，应考虑关闭它并评估 `use_auto_noise_removal` 及其聚类参数，而不是继续盲目增大。

### `phase_filter_range`

- 控制相位域滤波范围，主要影响相位抖动和局部异常的抑制。
- 增大可压制低频相位抖动和局部异常，但可能混合相位边缘并削弱小缺陷。
- 复杂边界、窄槽和精密计量区域应优先保护相位边缘。
- 调整后应同时比较相位残差、边缘偏移和缺陷保留率。

## 自动噪声与双边滤波

### `use_auto_noise_removal`

- 控制 SDK 是否自动估计聚类降噪参数。
- 开启时，SDK 会根据点云自动调整 `noise_removal_distance` 和 `noise_removal_point_number`，这两个手动参数不再直接生效。
- 点云中存在大量孤立噪声且场景变化较大时适合开启。
- 细小结构、尖端或遮挡区域成片消失时，应关闭自动策略并单独评估两个手动参数。

### `noise_removal_distance`

- 在手动聚类降噪模式下，控制点云分块或邻域的距离尺度。
- 距离判据放宽会清除更远的离群点，但也可能删除薄壁、悬臂和边缘点。
- 距离判据收紧会保护更多候选点，同时可能保留孤立噪声。
- 仅在 `use_auto_noise_removal` 关闭时调节，并结合点间距、局部曲率和最小特征尺寸判断。

### `noise_removal_point_number`

- 在手动聚类降噪模式下，控制局部块需要达到的点数支持。
- 提高要求会偏向保留连续主体、清除稀疏点。
- 小零件、尖端、孔口和遮挡区域可能因此被误删。
- 降低要求可以保护稀疏结构，但应依靠多视角一致性和置信度做后续复核。

### `use_auto_bilateral_filter`

- 控制 SDK 是否自动估计双边滤波的核大小和两个 sigma 参数。
- 表面噪声较连续且需要保护几何边缘时可以开启。
- 开启后，`bilateral_filter_kernal_size`、`bilateral_filter_depth_sigma` 和 `bilateral_filter_space_sigma` 的手动值会被忽略。
- 发现边缘偏移、小缺陷变钝或滤波结果不稳定时，应关闭自动策略并显式控制三个参数。

### `bilateral_filter_kernal_size`

- 控制双边滤波的空间核大小；SDK 字段中的 `kernal` 拼写保持不变。
- 增大核会扩大参与计算的邻域，使平面更平滑但更容易跨越孔边、台阶和薄壁。
- 减小核可保护局部边缘，但可能留下更多噪声。
- 仅在 `use_auto_bilateral_filter` 关闭时调节，并用人工边缘标准件验证。

### `bilateral_filter_depth_sigma`

- 控制双边滤波允许融合的深度差异尺度。
- 增大可提高平滑能力，但跨台阶和锐边混合的风险增加。
- 减小更能保护深度边缘，但点云噪声可能保留。
- 应和空间核、空间 sigma 一起调整，不能只根据点云视觉平滑度决定。

### `bilateral_filter_space_sigma`

- 控制双边滤波的空间距离尺度。
- 增大扩大空间平滑影响范围，适合连续大平面。
- 减小限制滤波只影响近邻点，适合孔边、窄槽和局部曲率变化区域。
- 调整后应检查边缘位置、局部曲率和缺陷宽度是否发生变化。

### `smooth_sigma`

- 控制 SDK 连续平滑的强度参数。
- 增大可以降低表面抖动，但会削弱峰谷、锐边和小尺寸缺陷。
- 减小更接近原始测量，但噪声和离群点会更明显。
- 正式计量应优先保证边缘和缺陷保真，再用标准件决定是否需要平滑。

## 点云范围、采样和坐标

### `downsample_distance`

- 控制 SDK 采集阶段的均匀空间降采样距离。
- 增大可以减少点数、内存和传输时间。
- 增大会降低小特征分辨率，并可能让后续边缘和孔口检测失去证据。
- 正式缺陷检测通常应保持原始采样，把可解释的降采样放到后续派生处理阶段。

### `truncate_z_min`

- 按 SDK 坐标系的 z 方向设置点云和深度图的下限。
- 项目不在 SDK 采集阶段使用这个边界，因为转台定位点可能在有效测量范围之外。
- 适合排除工作距离之外的背景、夹具或明显无关区域。
- 设置前必须确认坐标轴方向、单位和 `transform_to_camera` 的状态。
- 范围过窄会造成系统性缺失，范围过宽会增加噪声和后续计算量。

### `truncate_z_max`

- 按 SDK 坐标系的 z 方向设置点云和深度图的上限，与 `truncate_z_min` 配合使用。
- 项目会先用完整点云定位转台，再在输出主体点云时按这个边界标记和筛选点。
- 适合限制只处理工件所在深度带。
- 上限必须大于下限；改变坐标变换后，原来的范围不能直接照搬。
- 调整后要检查工件边缘、标记和夹具是否被裁掉。
- 相机斜放时，先确认转台标记和工件主体都在该 Z 范围内，否则二维图像仍在但点云定位可能失败。
- 使用窗口时会额外保存 `processed/valid.npy`，其中是 `source/points.npy` 中落在窗口内的点索引，便于复核和重新生成主体点云。

### `transform_to_camera`

- 控制 SDK 是否把点从标定板坐标系转换到相机坐标系。
- 项目的标记定位、转台变换、多视角融合和 STEP 配准依赖稳定且明确的坐标定义。
- 改变该开关会改变所有点的坐标语义，必须重新验证标定文件、旋转方向、高度方向和配准结果。
- 不要在同一批数据中混用不同坐标语义的点云。

### `roi`

- 限制 SDK 处理或输出的图像区域，包含位置和尺寸字段。
- `x`、`y` 定义区域起点，`width`、`height` 定义区域尺寸；具体步进和合法边界由设备的 ROI 能力决定。
- 视场中有大量稳定无关背景、且工件和标记位置固定时可以使用。
- ROI 过窄会造成标记定位失败、工件主体缺失或翻面后无法采集。
- 调整 ROI 后应覆盖所有转台角度和正反面姿态，并保留 ROI 配置用于追溯。

## 法向和几何证据

### `calc_normal`

- 控制 SDK 是否计算点云法向量。
- 法向可用于边界判断、入射角分析、跨视角一致性和高反区域诊断。
- 正式缺陷分析和反射研究通常应开启。
- 只做快速预览或明确不需要法向时可以关闭，以减少计算和存储开销。

### `calc_normal_radius`

- 控制法向估计所使用的邻域尺度。
- 增大通常让大平面的法向更稳定，但更容易跨越台阶和锐边。
- 减小更能保留局部曲率和小结构，但对稀疏点与噪声更敏感。
- 应根据点间距、最小特征尺寸和表面曲率选择，并用平面、台阶和圆柱标准件验证。

## 相机链路与传输

### `SetBandwidth(percent)`

- 设置相机数据传输带宽比例；它是相机对象的方法，不属于 `X1_CaptureOptions` 采集选项。
- 带宽比例越高，允许相机向主机发送的数据吞吐越大，采集传输等待通常越短，但更容易占满网卡、交换机或共享链路。
- 带宽比例越低，可以给同一网络上的其他设备留出余量，降低网络拥塞和 GigE 丢包风险，但可能降低可持续采集速率或增加单帧传输时间。
- 它不改变曝光、投影亮度、点云分辨率、滤波强度或测量精度；只改变数据传输节奏。
- 单相机独占网卡且没有丢包时通常不需要为提高画质调整它。
- 出现丢帧、传输超时、网卡占用过高或多设备抢占同一链路时，才需要降低并观察采集稳定性。
- 调整后应同时检查实际帧率、丢帧/超时日志、网卡利用率和完整扫描耗时；不要用点云数量判断带宽是否合适。
- 官方示例将该接口的输入限制在 SDK 规定的有效比例范围内，实际调用应以当前 SDK 返回成功为准，不要把示例中的某个值当作项目固定值。

### `GetBandwidth(percent)`

- 读取相机当前带宽比例，用于确认设备实际状态。
- 当前 Python 绑定只暴露了 `SetBandwidth`，没有暴露 `GetBandwidth`；项目不能假设可以从 `PyRVC.X1` 读取该值。
- 如果后续需要记录或恢复带宽设置，应在 Python 绑定中明确增加读取接口，再写入采集元数据。
